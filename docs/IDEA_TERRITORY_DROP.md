# TERRITORY DROP — 국가 영토 위로 떨어지는 팬케이크

Idea note v0.1 — 2026-09-17
상태: **아이디어 (PO 제안)**. 플랜 v0.3 의 단일 World Tower 와 병행 또는 대체 가능한 구조. 결정 전.

## 0. 요청 원문

> 아니면 국가 영토 위에 우르르 떨어지는 것도 재밌겠다. 실제 크기 비례로는 너무 작으니까 적절히 조절해서.

## 1. 개념

지구본(또는 평면 세계지도) 위에서, 사용자가 선택한 국가의 영토 위로 팬케이크가 쏟아진다.
Drop 시각(매 10분)이 되면 전 세계 국가 위로 동시에 팬케이크 비가 내리고, 각 나라의 땅 위에 팬케이크 더미가 쌓인다.

- 세계 총량이 아니라 **"우리 나라 땅이 팬케이크로 얼마나 덮였나 / 얼마나 높이 쌓였나"** 가 눈에 보인다.
- 국가 순위(플랜 §16)가 숫자표가 아니라 **지형**이 된다. 일본 열도 위 팬케이크 산, 한반도 위 팬케이크 산이 나란히 보인다.
- Collapse Day(§49)와도 자연스럽게 맞는다: 각 나라의 22:00 에 **그 나라 땅 위 더미**가 무너진다. 하나의 탑에서 국가별 Release 를 하는 v1 의 어색함(공중에 고정된 다른 나라 팬케이크)이 사라진다.

## 2. 스케일 문제와 조절

실제 비례로는 팬케이크(10 cm)가 국토(수백 km) 위에서 픽셀 이하다. 따라서 **팬케이크 크기를 국가 크기에 맞춰 키운다**.

| 안 | 팬케이크 직경 | 효과 |
| --- | --- | --- |
| A. 전 세계 동일 | 예: 20 km | 대국은 넓게 덮이고 소국은 몇 장으로 덮인다. 개수 차이가 그대로 면적 차이로 보임. 소국은 금방 "탑"이 된다. |
| B. 국가 면적 비례 | 직경 ∝ √(국가 면적) | 모든 나라가 같은 개수에서 같은 정도로 덮인다. 공정하지만 "일본 3,821,492개" 가 시각적 크기와 안 맞음. |
| C. 혼합 | 직경 = clamp(√면적 × k, 최소, 최대) | 극단(러시아 vs 싱가포르)만 잘라낸다. **권장 출발점.** |

어떤 안이든 팬케이크의 **실제 높이(플랜 §13 Tower Height)** 는 별도로 유지한다. 시각적 스케일과 기록용 실제 치수는 다른 값이다.

## 3. 물리 관점 (Phase 0 결과 반영)

Phase 0 프로토타입([`benchmarks/phase0-2026-09-17.md`](./benchmarks/phase0-2026-09-17.md))에서 확인된 것:

- 자유 강체 물리로는 팬케이크가 **탑을 이루지 않고 옆으로 흘러 언덕**이 된다(높이 효율 3%).
- 시럽 규칙(접촉 시 정착) + 드레이프 규칙(받침 면에 순응)을 넣어야 탑이 선다(효율 ~100%).

Territory Drop 은 오히려 **언덕이 자연스러운 형태**다. 넓은 영토 위에 흩뿌려 쌓이는 것이므로, 스폰 퍼짐을 크게 두고(영토 폴리곤 안에서 균등 분포) 시럽 규칙만 켜면 된다. 탑을 세우기 위한 억지 규칙이 덜 필요하다.

시뮬레이션 코어(`apps/physics-prototype/src/sim/TowerSim.ts`)는 스폰 위치를 함수로 바꾸면 그대로 쓸 수 있다: 현재 `spawnMode: 'axis' | 'top'` 에 `'region'` (폴리곤 내 균등 샘플링) 을 추가하는 정도.

성능 관점: 국가별 더미는 서로 독립이므로 Physics Worker 를 **국가 단위로 분할**할 수 있다. 플랜 §9 의 Simulation Group 을 국가별로 두면 병렬화가 자연스럽다.

## 4. 단일 탑과의 관계 (결정 필요)

| | World Tower (플랜 v0.3) | Territory Drop |
| --- | --- | --- |
| 핵심 이미지 | 하나의 거대한 탑, 우주까지 | 지구를 덮는 팬케이크 지형 |
| 국가 경쟁 | 순위표 + 탑 안의 국기 | 지형 자체가 순위 |
| 높이 목표(SPACE) | 자연스러움 | 국가별 더미 높이로는 어색. "가장 높은 더미" 또는 "전 세계 팬케이크 총 두께" 로 재정의 필요 |
| Find My Pancake | 탑 안에서 찾기 | 우리 나라 땅 위에서 찾기 (더 친근) |
| Collapse Day | 국가별 Release 가 어색 | 국가별 22:00 붕괴가 자연스러움 |
| 렌더링 | 수직으로 긴 하나의 구조 | 지구본 + 수백 개 더미. 카메라/LOD 가 더 복잡. |

가능한 조합:

1. **Territory 를 메인으로**, World Tower 는 폐기.
2. **둘 다**: Territory 가 라이브 화면, 모든 팬케이크가 동시에 World Tower 에도 존재(같은 데이터, 두 개의 시각화). 데이터 구조상 가능하지만 "실제로 저기에 있다" 는 감각이 둘로 갈린다.
3. **Territory 가 Drop 화면, 붕괴 후 팬케이크가 World Tower 로 이동** 같은 서사 — 복잡.

## 5. PO 결정 항목

1. World Tower 와 Territory Drop 중 무엇이 메인 이미지인가 (또는 병행).
2. 팬케이크 시각 스케일 규칙 (§2 의 A/B/C).
3. 지구본(3D) vs 평면 지도(2.5D).
4. 영토 데이터 출처와 분쟁 지역 처리 원칙 (정치적 민감 사안 — 표준 데이터셋(Natural Earth 등)을 그대로 쓰고 자체 판단을 하지 않는다).
5. SPACE 높이 목표의 재정의 여부.

이 결정 전까지 Phase 0/1 은 그대로 진행한다. 두 안 모두 "각 팬케이크가 독립 Instance 로 실제 위치를 가진다"는 원칙과 렌더링/물리 코어를 공유하기 때문이다.
